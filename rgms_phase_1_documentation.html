01

ขอบเขตโครงการ (Project Scope)

ระบบบริหารจัดการทุนวิจัย มฟล. (RGMS) ในระยะ MVP เฟส 1 มุ่งเน้นกระบวนการต้นน้ำตั้งแต่ “การเปิดรับสมัคร จนถึงการออกประกาศผลจัดสรรทุน” เพื่อรองรับขั้นตอนการคัดเลือกและอนุมัติทุนวิจัยอย่างรวดเร็วและเป็นระบบ

In-Scope (ขอบเขตใน MVP Phase 1)

รวมในระบบ
  • การจัดการรอบทุน: ประกาศเปิด/ปิดรับสมัครตามกรอบเวลา
  • โปรไฟล์นักวิจัย & นำเข้าไฟล์: กรอกประวัติ RS-01 ส่วน ข และสกัดข้อความอัตโนมัติจาก .docx
  • ตรวจสอบงบประมาณ: ตรวจเกณฑ์ Per-Tier และเตือนเพดานย่อย 25% (เดินทาง/ครุภัณฑ์)
  • School Endorsement: การตรวจและรับรองระดับสำนักวิชาโดยประธานวิจัย/คณบดี
  • 2-Track Parallel Review: แยกการประเมินแทร็กเนื้อหา (อนุกรรมการ) และแทร็กการเงิน (เจ้าหน้าที่ Claim งาน)
  • Field-Level Locking & Auto-Routing: ล็อกฟิลด์ส่วนที่ผ่านแล้ว และส่งเฉพาะแทร็กที่ไม่ผ่านซ้ำ
  • สรุปมติ & ประกาศผล: บันทึกมติ คกก.ส่งเสริมฯ และสร้างร่างเอกสารส่งลงนาม e-Office

Out-of-Scope (ยกไปทำในเฟสถัดไป)

ถัดไป (Phase 2+)
  • ทำสัญญารับทุน: การออกสัญญาและลงนามรับทุนออนไลน์
  • การเบิกจ่ายเงินงวด: กระบวนการเบิกจ่ายเงินตามงวด 50% / 40% / 10%
  • ติดตามรายงาน: การส่งรายงานความก้าวหน้า (Progress Report) และรายงานฉบับสมบูรณ์
  • การตรวจเอกสารการเงินปลายน้ำ: แบบฟอร์ม วจ.1 ถึง วจ.9
  • การเปลี่ยนแปลงสัญญา: คำขอขยายเวลา / คำขอปรับเปลี่ยนรายละเอียดงบประมาณระหว่างดำเนินโครงการ
02

ขั้นตอนการทำงานแยกตามบทบาท (Role-Based Workflow)

นักวิจัย (Principal Investigator)

ผู้ยื่นขอรับทุนวิจัย และแก้ไขข้อเสนอโครงการ

01. กรอกประวัติส่วนตัวและผลงาน (RS-01 ส่วน ข) ในระบบโปรไฟล์ครั้งเดียว เพื่อใช้ซ้ำได้กับทุกข้อเสนอทุน
02. เลือกประเภททุน และนำเข้าข้อความจากไฟล์ RS-01 (.docx) ลงแบบฟอร์มอัตโนมัติ
03. เสนองบประมาณผ่านไฟล์ Excel 17.2 (.xlsx) หรือ Web Form พร้อมระบบแจ้งเตือนตรวจเพดานงบประมาณสด
04. แก้ไขฟอร์มเฉพาะส่วนที่ได้รับอนุญาตให้แก้ไข (Field-Level Unlocked) เมื่อได้รับแจ้งส่งกลับแก้ไข (Revise Loop)
ประธานวิจัย / คณบดี

กลั่นกรองและรับรองในระดับสำนักวิชา

01. ตรวจสอบรายละเอียดข้อเสนอโครงการของนักวิจัยสังกัดสำนักวิชาตนเอง
02. กดทำรายการ “รับรอง (Endorse)” เพื่อส่งต่อส่วนกลาง หรือ “ส่งกลับแก้ไข (Return)” พร้อมระบุข้อคิดเห็น
เลขาสำนักวิชา

ติดตามสถานะและประสานงาน (Read-Only)

01. เข้าดูแดชบอร์ดภาพรวมเพื่อติดตามสถานะความคืบหน้า เอกสาร และคอมเมนต์ของนักวิจัยในสำนักวิชาตนเองแบบ Read-Only
เจ้าหน้าที่ส่วนวิจัย (Operations)

ผู้ดูแลระบบ บริหารรอบทุน และประสานงาน

01. ประกาศเปิด/ปิดรอบทุน และตั้งค่าเพดานงบประมาณตามประเภททุน
02. ตรวจความครบถ้วนของเอกสาร (Screening) และมอบหมายคณะอนุกรรมการพิจารณาเนื้อหา
03. ทำหน้าที่ Admin Reassign เพื่อโอนย้ายคิวตรวจการเงินกรณีผู้ตรวจเดิมไม่สะดวกปฏิบัติงาน
04. สรุปโครงการเข้าวาระ คกก.ส่งเสริมฯ บันทึกมติ และสร้างร่างประกาศผลเพื่อเสนอลงนามผ่าน e-Office
เจ้าหน้าที่การเงินส่วนวิจัย (Finance)

ผู้ตรวจสอบความถูกต้องงบประมาณ

01. กด “Claim” รับตรวจงบประมาณโครงการจากคิวกลางเพื่อผูกเป็นผู้ตรวจประจำโครงการ
02. ตรวจสอบตารางงบประมาณ 17.2 บันทึกข้อคิดเห็นการเงิน และกดรับรองแทร็กการเงิน
คณะอนุกรรมการพิจารณา

ผู้ประเมินคุณภาพเชิงเนื้อหา

01. ประเมินคุณภาพข้อเสนอเชิงคุณภาพ (Comment-Based) ในแทร็กเนื้อหา และให้คำวินิจฉัยโดยไม่มีการให้คะแนน Rubric
ผู้บริหาร / คกก.ส่งเสริมฯ

ผู้อนุมัติจัดสรรทุนและออกประกาศ

01. พิจารณาสรุปโครงการที่ผ่านการรับรองครบทั้ง 2 แทร็ก บันทึกมติจัดสรรทุน และลงนามประกาศผลผ่านระบบ e-Office

04

กฎทางธุรกิจและทางแก้จุดขัดแย้ง (Business Rules & Fixes)

1

Comment-Based Review 100%

ตัดระบบคะแนน Rubric 100 คะแนนออก ปรับมาใช้ระบบการให้ข้อคิดเห็น คอมเมนต์ และคำวินิจฉัยเชิงคุณภาพตามกระบวนการจริงของ มฟล. เพื่อลดความซ้ำซ้อนและสะท้อนการทำงานจริง

Logic Flag: NO_RUBRIC_SCORE Qualitative Feedback Only
2

Field-Level Locking

ในรอบการแก้ไข (Revise Loop) ฟอร์มฝั่งนักวิจัยจะถูกล็อกเป็น Read-Only เฉพาะในส่วนของแทร็กที่ได้รับการรับรองแล้ว เพื่อป้องกันไม่ให้นักวิจัยแก้ไขงบประมาณหรือเนื้อหาข้ามส่วนที่ผ่านการตรวจไปแล้วโดยไม่ได้รับอนุญาต

Security Rule: LOCK_PASSED_FIELDS
3

Auto-Routing Revise Loop

นักวิจัยไม่ต้องเลือกแทร็กส่งตรวจซ้ำเอง ระบบจะตรวจสอบสถานะเดิม และส่งฉบับแก้ไขไปให้ผู้ตรวจในแทร็กที่ไม่ผ่านโดยอัตโนมัติ (เช่น หากไม่ผ่านการเงิน ระบบจะส่งตรงถึงเจ้าหน้าที่การเงินคนเดิม)

Automation: AUTO_ROUTE_REJECTED_TRACK
4

Admin Reassign (Unclaim & Queue Transfer)

หากเจ้าหน้าที่การเงินที่กด Claim งานไว้ลาหยุดหรือโอนย้าย เจ้าหน้าที่ส่วนกลาง (Operations) สามารถกด Unclaim เพื่อปลดล็อกคิวงานคืนสู่คิวกลาง หรือโอนย้ายให้ผู้ตรวจคนอื่นได้ทันที เพื่อป้องกันคิวงานค้าง

Admin Control: OVERRIDE_CLAIM_QUEUE
05
